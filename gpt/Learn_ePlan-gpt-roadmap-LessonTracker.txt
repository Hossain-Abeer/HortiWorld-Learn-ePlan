================================================================================
EPLAN ONE-WEEK CRASH — LESSON TRACKER
================================================================================
Dummy project : DOL motor starter panel (industry-standard reference)
Purpose       : Recognition-level EPLAN fluency in 7 days; productive from
                day 1 at Hortiworld, not expert.
Tool          : EPLAN Education (student). 40-page cap. Non-portable files.
                Personal practice ONLY — never production at Hortiworld.
Format        : Mirrors your design/dev trackers. One subsec at a time.
                Per subsec I (assistant) will:
                  (1) explain concept
                  (2) step-by-step how to do it
                  (3) state evidence to send back
                  (4) on pass, write a conclusion, tick [x], proceed.
Repo/naming   : Files saved under your usual workspace. No code artefacts.

HOW TO USE
----------
- Work top to bottom. Day boundaries are soft; hours are evenings/weekends.
- Tick [x] only after your evidence passes my check.
- If a subsec blocks you, work the Debug lines before advancing.
- One chat, continuous. Paste evidence back into this chat.
- Do NOT attempt Section 6+ before Sections 2-4 are ticked — the mental
  model must be right before potential trackers make sense.

LEGEND
------
[ ]  not started
[~]  in progress
[x]  done + verified

TYPE MARKERS
------------
  Type: lesson     I explain the concept; you listen, then attempt
  Type: exercise   you perform it in EPLAN Education
  Type: verify     you report back; I check and tick
  Type: self-check you sanity-test against expected result
  Type: writing    short writeup to consolidate learning

SCOPE (HONEST)
--------------
Target after 7 days:
  - recognise the EPLAN interface and every ribbon tab by name
  - understand & apply IEC 81346 tags (=loc+fn-prod)
  - draw a 1-page DOL power circuit
  - draw a control circuit with cross-references working
  - model a PLC input card with terminal strip
  - place potential trackers and split power distribution over 2 pages
  - recognise what Pro Panel, macros, Data Portal, auto-BOM do — and why
    to ignore them for now.
Not target:
  - fluency, macros, EPLAN Pro Panel, EPLAN Fluid, multi-user, project
    data management, script-based automation, full IEC 81346 depth beyond
    what Hortiworld panels use.

SECTION 2 — IEC 81346 DEVICE TAGGING (Day 2, ~2 h)  [PRIORITY CONCEPT 1]
================================================================================

[ ] 2.1  CONCEPT LESSON
    Type: lesson
    Objective: explain =Location+Function-Product; contrast with KiCAD
               reference designators (R1, C2) which have no location.
    Feature: none (concept).
    Action: I explain:
              =  location (system/plant)          e.g. =GH1 (greenhouse 1)
              +  function (subsystem/panel)        e.g. +CP1 (control panel 1)
              -  product (device in the function)  e.g. -K3 (contactor 3)
              letter codes per IEC 81346 / EN 61346-2: K=contactor,
              Q=MCB, F=protective, M=motor, X=terminal, S=switch, H=lamp
    Evidence: you translate these 5 English identifiers to 81346 form:
              (a) 3rd contactor in control panel 1, greenhouse 1
              (b) motor 1 in machine room 2
              (c) main circuit breaker in panel 2, line 1
              (d) emergency-stop pushbutton in panel 1
              (e) terminal strip in panel 1
    Verify: 5/5 correct format.
    Debug:  you put product before function -> wrong; location=function-product.

[ ] 2.2  APPLY IN EPLAN
    Type: exercise
    Objective: insert a contactor and see EPLAN auto-tag it from the
               page's location+function.
    Feature: Insert > Symbol > IEC_symbol library > contactor coil; the
             full DT field shows =GH1+CP1-K1.
    Action: place a contactor coil on Page 1; open its Properties; find
            the full device tag field.
    Evidence: paste the full device tag shown; describe where the fields
              =GH1, +CP1, -K1 sit separately.
    Verify: full tag matches Section 2.1 rules.
    Debug:  only shows -K1 -> page has no structure identifier; go back 1.2.

[ ] 2.3  RENAME / RENUMBER
    Type: exercise
    Objective: renumber a device and observe automatic update of its
               cross-references.
    Feature: right-click device > Properties > Device tag; or Utilities >
             Renumber.
    Action: change -K1 to -K3; save.
    Evidence: describe what changed and whether any cross-reference
              jumped to -K3 automatically.
    Verify: all references updated; no orphan.
    Debug:  unchanged references -> device was copied as "graphic" not
            "device"; delete and re-insert as device.

[ ] 3.1  LAYOUT PLAN

    Action: I describe the standard DOL layout:
              top: L1 L2 L3 PE potential rail (or 3-line busbar)

    Evidence: your one-line mental sketch described in text.
    Verify: sequence is electrically correct.
    Debug:  overload after motor -> wrong; overload is in series before

[ ] 3.2  INSERT POWER SYMBOLS
    Type: exercise

    Feature: Insert > Symbol; IEC library; search by symbol name.
    Action: place each symbol; assign device tags Q1, K1, F1, M1.
    Evidence: list of placed symbols with device tags.
    Verify: 4 device groups present; K1 is a multi-pole contactor, not
            a single contact.
    Debug:  cannot find F1 thermal overload -> use IEC library "overload
            relay" symbol; assign F1.

[ ] 3.3  WIRING (autoconnect & T-nodes)
    Type: exercise
    Objective: connect the power circuit; EPLAN auto-generates connection
               lines when symbols align on the same grid.
    Feature: Autoconnect lines; T-node; break point if crossing.
    Action: wire L1-L2-L3 top to Q1, Q1 to K1, K1 to F1, F1 to M1.
            Add PE line to motor frame.
    Evidence: describe which wires EPLAN auto-drew vs which you manually
              drew; count of connections.
    Verify: 4 horizontal potentials + PE, no missed junction, no crossing
            without break point.
    Debug:  auto-connect not drawn -> symbols not on the same grid Y

[ ] 3.4  CONNECTION POINT NUMBERS & WIRE NUMBERS

    Evidence: 3 example wire numbers; describe default rule.
    Verify: numbering covers all power wires; no duplicates.
    Debug:  nothing numbered -> project settings block auto-numbering;

[ ] 4.1  CONCEPT LESSON — CROSS-REFERENCE
    Type: lesson
    Objective: explain how EPLAN auto-generates "coil ↔ aux contact"
               references and why KiCAD net-labels do NOT do this.
    Action: I explain:
              - a device is one object with many representations
              - K1 has a coil on Page 2, an NO aux contact on Page 2,
                a main contact on Page 1 — all share -K1
              - EPLAN writes "/2.3" style references automatically
    Evidence: paraphrase why KiCAD cannot replicate this.
    Verify: answer captures "device is logical, not graphical".
    Debug:  "net labels do the same" -> no; net labels link nets, not
            devices; contactor aux feedback is a device concept.

[ ] 4.2  CONTROL CIRCUIT LAYOUT
    Type: lesson
    Objective: plan 230 V AC control circuit with E-stop, start, stop,
               seal-in, contactor coil, overload NC.
    Action: I lay out the standard ladder:
              L (230 V) -> F2 (control fuse) -> S0 (E-stop NC)
              -> S1 (stop NC) -> S2 (start NO) || K1.13-14 (seal-in)
              -> F1.95-96 (overload NC) -> K1 coil (A1/A2) -> N
    Evidence: your textual ladder confirmation.
    Verify: sequence electrically correct.
    Debug:  seal-in across S2 only -> wrong; seal-in across S2 (parallel).

[ ] 4.3  DRAW & TAG

    Verify: K1 appears as coil + aux on Page 2, main on Page 1, same tag.
    Debug:  K1 aux not recognised as same device -> inserted as new

[ ] 4.4  VERIFY AUTO CROSS-REFERENCES

SECTION 5 — TERMINAL STRIP & PLC I/O MAPPING (Day 5, ~3 h)
                                            [PRIORITY CONCEPT 2]
================================================================================

[ ] 5.1  CONCEPT LESSON — PLC I/O IN EPLAN
    Type: lesson
    Objective: explain how a Mitsubishi FX/Q input card appears in EPLAN:
               a "PLC box" function with I/O addresses (X0..X7, Y0..Y7)
               and channel-level connection points.
    Action: I explain:
              - Mitsubishi input addressing: X (input), Y (output), octal
                grouping (X0..X7, X10..X17 etc.)
              - EPLAN PLC box = a function with a PLC-specific connection
                point pattern
              - each X-point becomes a connection point number on the
                symbol; the field is editable (X0, X1, ...)
    Evidence: paraphrase X vs Y and octal grouping.
    Verify: correct.
    Debug:  "hex grouping" -> wrong; Mitsubishi is octal.

[ ] 5.2  PLC BOX — 8 PNP SENSORS
    Type: exercise
    Objective: model a single input card with 8 PNP 24 V DC sensors.
    Feature: Insert > Symbol > PLC > PLC box (8-channel), IEC library.
    Action: place PLC box on a new page under =GH1+CP1; assign device tag
            -A1 (or Mitsubishi-style -A1); set 8 inputs to X0..X7; add
            8 sensor symbols upstream, tags -B1..-B8.
    Evidence: pasted list of 8 PLC address + sensor tag pairs.
    Verify: 8 pairs; addresses octal-correct (X0..X7 is fine).
    Debug:  can't edit X-address -> connection point properties, not
            device tag; open per-Pin properties.

[ ] 5.3  TERMINAL STRIP
    Type: exercise
    Objective: insert -X1 terminal strip between field sensors and PLC
               input card, matching a real cabinet.
    Feature: Insert > Terminal; Terminal strip editor.
    Action: create X1 with at least 6 terminals (24V, 0V, X0, X1, X2,
            PE); assign each terminal to a wire side.
    Evidence: terminal list with numbers and net names.
    Verify: each sensor wire passes through a terminal; +24 V and 0 V
            buses present.
    Debug:  terminal floating -> attach to a connection line; EPLAN
            requires the terminal on the wire, not next to it.

[ ] 5.4  PNP WIRING CHECK
    Type: self-check
    Objective: confirm 3-wire PNP topology (brown=+24, blue=0V, black=
               signal to X input).
    Action: describe the wiring for one sensor.
    Evidence: 3-line description.
    Verify: PNP topologically correct.
    Debug:  black to 0V -> NPN not PNP.

    Verify: correct voltage flow.
    Debug:  missing isolation -> transformer output must be re-protected
